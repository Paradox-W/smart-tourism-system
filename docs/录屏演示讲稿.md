### 1.2 需求与功能（1分钟）

🎙️ 系统一共六大功能模块：

🎬 展示功能列表（PPT或截图）

🎙️ **旅游推荐**——按热度、评分给用户推荐景点，支持关键词搜索和分类筛选。

**路线规划**——这是我们的核心功能，支持单点最短路径和多点参观路线规划，还考虑了不同交通工具和道路拥挤度。

**场所查询**——选中某个景点后，查找附近的超市、卫生间等设施，按实际路径距离排序。

**旅游日记**——用户可以写日记、评分、搜索，还实现了全文检索和Huffman压缩存储。

**日记交流**——按目的地筛选日记，精确查询用HashMap，全文检索用倒排索引。

**美食推荐**——按热度、评分、距离推荐美食，支持编辑距离模糊搜索。

⏸️

### 1.3 技术架构（1分30秒）

🎬 切到架构图/PPT

🎙️ 架构方面，我们采用的是B/S架构，前后端分离。

**后端**用C++17开发，HTTP服务用的是cpp-httplib，数据库是SQLite3，构建工具CMake。后端内部采用五层分层架构——HTTP路由层、响应封装层、业务逻辑层、算法引擎层、数据访问层，各层单向依赖，职责清晰。

**前端**用Vue3 + TypeScript + Element Plus + TailwindCSS，地图用HTML5 Canvas绘制。通过Axios调后端的RESTful API，前端开发服务器代理到后端8080端口。

🎙️ 大家可以看一下我们的项目结构，后端按algorithm、service、repository、server分层，前端按views、api、components组织，比较清晰。

## 第二部分：核心算法介绍（约2分30秒）

🎙️ 下面介绍我们实现的核心算法，一共有九个，全部自实现数据结构，没有用STL容器。

🎬 展示算法列表（PPT或代码目录）

### 2.1 旅游推荐 — Top-K堆排序（40秒）

🎙️ 旅游推荐的核心是Top-K问题。用户通常只看前10个景点，没必要把所有景点排完序。我们用大根堆实现Top-K算法，时间复杂度是O(n + k log n)，比全量排序O(n log n)更高效，而且支持数据动态变化。

### 2.2 路线规划 — Dijkstra + TSP（1分钟）

🎙️ 路线规划是我们最核心的模块。单点寻路用Dijkstra算法，支持三种策略：最短距离、最短时间（考虑道路拥挤度）、混合交通工具（自行车、步行、电瓶车，用多层图建模）。

多点参观路线是TSP问题，NP难的，我们用最近邻启发式加2-opt局部优化，在时间和精度之间取得平衡。

### 2.3 日记交流 — 倒排索引 + Huffman压缩（30秒）

🎙️ 日记的全文检索，我们实现了倒排索引，支持TF-IDF排序和AND查询。日记压缩存储用的是Huffman编码，从频率统计、建树到编解码全部自实现。

### 2.4 美食推荐 — 编辑距离模糊搜索（20秒）

🎙️ 美食搜索支持模糊匹配，用编辑距离动态规划算法计算相似度，返回最接近的Top-K结果。

## 第三部分：系统演示（约4分钟）

### 3.1 启动后端（30秒）

🎬 打开终端，cd到后端目录

🎙️ 先启动后端服务。

🎬 运行 SmartTourismSystem.exe

🎙️ 可以看到服务器已经启动，路由注册完成，监听在8080端口。

### 3.2 API测试（1分30秒）

🎬 打开浏览器/Postman

🎙️ 我们先测一下健康检查接口。

🎬 访问 http://localhost:8080/api/health

🎙️ 返回200，服务正常运行。

🎬 访问 http://localhost:8080/api/spots/recommend?limit=5

🎙️ 这是景点推荐接口，返回按热度排序的景点列表，每个景点包含名称、类型、热度、评分等信息。

🎬 访问 http://localhost:8080/api/spots/search?keyword=公园

🎙️ 这是搜索接口，输入关键词就能搜索景点，底层用Trie前缀树实现。

🎬 访问 http://localhost:8080/api/debug/db

🎙️ 这是调试接口，可以直接查看数据库里的数据。

### 3.3 前端页面演示（2分钟）

🎬 打开浏览器，访问前端页面 http://localhost:5173

🎙️ 现在看前端。这是我们的推荐页面——

🎬 RecommendView

🎙️ 可以看到景点卡片展示，支持按热度、评分排序，支持分类筛选。点击景点可以看详情。

🎬 切到 MapView

🎙️ 这是地图页面，用Canvas绘制了路网图。每个节点可以点击选择，点击"规划路线"后，系统调用Dijkstra算法计算最短路径，并在地图上高亮显示。

🎬 切到 FacilityView

🎙️ 场所查询页面，选择一个节点后，系统用Dijkstra计算到各设施的实际路径距离，然后排序展示。注意这里不是直线距离，是真实可达路径的距离。

🎬 切到 DiaryView

🎙️ 日记管理页面，支持创建、编辑、删除日记。这里有个亮点——Huffman压缩演示，点击压缩后可以看到压缩率。还支持全文检索和精确查找两种搜索模式。

🎬 切到 FoodView

🎙️ 美食推荐页面，支持按热度、评分、距离排序，支持菜系筛选。搜索框支持编辑距离模糊匹配，比如输入"宫堡鸡丁"也能搜到"宫保鸡丁"。
